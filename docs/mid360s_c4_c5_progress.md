# MID360S C4/C5 机体位姿与健康门控进度（2026-09-27）

**安装信息更新**：用户随后确认雷达与机体同轴、在中轴线上方。下文“实测 `T_I_B` 与 `reviewed: true` 必填”描述的是当时实现；当前默认参考点已改为雷达原点，雷达到机体原点高度可选。健康门控与地面未解锁标定要求保留。

## 已实现与验证

- LIO 增加 `/LioHealth`：epoch、有效激光校正序号、锚点/状态时间、最终匹配数、点到平面 RMS、六维观测信息矩阵最小/最大特征值比、重力向量及原因。六维矩阵只使用最终有效点的位姿雅可比，不混入滤波器先验。缺匹配或扫描无效不增加校正序号。
- 原始 LIO odom 的 child frame 改为 `imu`，与其实际 IMU 原点姿态和机体系 twist 一致；机体控制原点只在 Python 桥接层通过已复核的 `T_I_B` 转换。
- 高频消息与健康消息按相同真实 IMU 时刻发布。源时间与锚点超过 250 ms 时健康状态为 LOST；匹配少于 200、RMS 超过 0.15 m 或几何比不超过 1e-4 时为 DEGRADED。
- Navigation 仅在安装文件明确 `reviewed: true`、至少 2 秒静态 IMU、连续 10 个合格激光校正、同 epoch 和时间戳的健康/里程计、接收与源时间新鲜时允许基点标定。基点标定还要求飞控报告未解锁。运行中每个控制周期调用 `get_pose()`，即使全部话题停发也会重新检查年龄；失效时撤销水平导航、关闭 PID、清除当前轨迹推进并使用既有实时控制接口发零水平/偏航命令。LOST 锁存，只有明确未解锁的地面重置能清除。
- 基点计算用估计重力定竖直，以校准时机体前向的水平投影定航向。机体控制原点始终用 `T_O_B=T_O_I T_I_B` 的旋转杆臂计算。测试覆盖原地旋转 90° 时 1 m 安装杆臂产生的机体位置位移。
- 桥接还提供单个线程安全的六自由度机体快照，包含 W 系位置、旋转矩阵、含 `omega×t_I_B` 杆臂项的 W 系线速度及 B 系角速度；Navigation 现有水平控制接口仍只取位置与 yaw。
- ROS 2 Humble Release 编译和 12.63 秒实测静态包回放通过。一次回放得到 121 次低频校正、2135 个高频/健康配对；健康状态 2109 TRACKING、26 LOST。启动和回放调度会影响这些计数。Python 定向测试 9 项通过，其中包含静止窗、连续校正、地面标定及无消息超时锁存。
- 队列上限和 `imu` child frame 更新后的最终编译、回放再次通过：110 次低频校正、2110 个高频/健康配对，时间单调、frame 正确、pose 协方差对角项均正。这次没有触发 LOST；前次的 26 条 LOST 反映回放启动时的积压，可用于验证拒绝路径，不能据此推断现场稳定性。

## 未完成和飞行阻断项

- 安装 `T_I_B` 的实测平移、旋转、机体原点及方向仍未提供；生产安装 JSON 和生产 LIO YAML 未生成，`server_ros.py` 拒绝生产启动。模板已按方案写入固定厂家 `T_I_L`，它与机体安装 `T_I_B` 是不同变换，仍需台架核验方向。
- 上述短静态包不能签收动态旋转/平移方向、真实位置精度、单平面退化场景、网络积压及板载视觉负载下的尾延迟。首轮几何门槛可能需依据实景复核。
- 控制失效路径只复用了既有实时控制零命令；这不能证明飞控会悬停，也尚未验证机载 FC_Server 的可靠模式切换。未测安装、未完成动态/控制验证前禁止飞行。
- 旧 D500 避障消费者和机体协方差杆臂变换仍待完成；现有 Navigation 只消费水平位置和 yaw。
